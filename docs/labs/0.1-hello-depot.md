# Lab 0.1: Hello, Depot

## Goal
Create the Depot solution with a domain model and tests that enforce the core rule: on-hand stock never goes negative.

## What I built
- Solution with three projects: `Depot.Core` (domain, no dependencies), `Depot.Cli` (console report), `Depot.Core.Tests` (xUnit).
- `Product` and `StockLine` records.
- `InventoryService` with AddProduct, OnHand, Receive, Ship and Report.
- Domain exceptions: `UnknownSkuException`, `InsufficientStockException`.
- Three unit tests covering receiving, shipping, and refusing to ship more than is on hand.

## Break-it step
Commented out the insufficient-stock check in `InventoryService.Ship`. One test went red:

```
Failed Depot.Core.Tests.InventoryServiceTests.Shipping_more_than_is_on_hand_is_refused
Assert.Throws() Failure: No exception was thrown
Expected: typeof(Depot.Core.InsufficientStockException)
Failed!  - Failed: 1, Passed: 2, Skipped: 0, Total: 3
```

The console report still ran normally, because nothing in the report path ships too much. So the rule can only be protected by a test, not by checking the app by hand. Restored the check, and the tests were back to 3/3.

## What broke and how I fixed it
- `rm -f` failed in PowerShell because `rm` there is an alias for `Remove-Item`, where `-f` is ambiguous. Fixed with `Remove-Item <path>`.
- `dotnet run --project src/Depot.Cli` failed with `MSB1009: Project file does not exist` because the terminal was inside `src\Depot.Cli`, so the relative path pointed nowhere. `dotnet test` from that folder silently ran no tests. Fixed by running all commands from the repo root.
- The projects target net8.0 (the SDK that was installed). Retargeting to .NET 10 is scheduled for the start of Lab 0.2.
